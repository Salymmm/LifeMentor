# 任务日期最小支持

## 目的与范围

为成员 A 的智能提醒与日历功能提供任务日期基础。用户已确认负责日期支持，并选择先手动设置日期、保留成员 B 的 AI 拆解协议。本次只实现日期的保存和编辑；系统通知、日历和 Health Connect 分阶段实现。

## 已选方案与取舍

- **采用：手动设置。** AI 继续返回现有字符串行动列表。周任务和每日行动由用户选择日期，改动集中在数据模型、任务存储和目标页。
- **暂缓：AI 自动安排。** 需要同时调整提示词、严格 JSON 校验、任务解析及 Python 评测。本阶段不改这些接口，避免影响已合入的 B 功能。

## 数据约定

- 在 `TaskItem` 最后添加 `dueDate: Long? = null`，保持既有构造调用兼容。
- `dueDate` 表示一个日历日期，不包含时刻；保存为该日期 UTC 零点的 Unix 毫秒值，与 [Material 3 日期选择器](https://developer.android.com/reference/kotlin/androidx/compose/material3/DatePickerState) 的日期值一致。
- 显示及后续提醒均先按 UTC 将值还原成日期；提醒功能再按设备当前时区安排该日期的提醒时刻，不能将保存值直接当成当地提醒时间。
- 旧 JSON 未包含该字段、或字段为 JSON null 时，读取为 null。不迁移、不重写、不为旧任务猜测日期。
- 保存和清除日期时仅改变目标任务的 `dueDate`，保留完成状态、XP、任务层级、标题及关联 ID。

## 用户操作

- 在目标详情的周任务（level 2）和每日行动（level 3）右侧显示“设置日期”或 `YYYY-MM-DD`。
- 点击日期入口打开系统风格的 Material 3 日期选择弹窗。
- 用户可以保存日期、清除已有日期，或取消且不改变原值。
- 季度里程碑（level 1）不增加日期入口。
- 修改后立即保存，重新进入应用后仍显示该日期。长标题换行，避免挤掉日期按钮。
- AI 拆解与手动新增行动仍默认没有日期；本次不改变主页的今日行动筛选逻辑。

## 实现边界

- 沿用当前 Kotlin、Compose、JSON 存储，不添加依赖，不迁移 Room。
- 主要修改 `GameModels.kt`、`GameStore.kt`、`GoalsViewModel.kt`、`GoalsScreen.kt`；日期换算若需要复用，集中在一个小型日期工具中。
- 不修改 B 的 `Prompts.kt`、`JsonExtract.kt`、评测脚本或聊天流程。
- 用户再次明确：B 负责的 AI 功能发现问题时先询问，不自行修复。本次仅运行现有回归测试，不修改其实现。
- 在新克隆的独立副本 `LifeMentor/` 的 `codex/task-dates` 分支工作，不推送远端。

## 验收

1. 单测证明旧 JSON 可读、日期可往返保存、清除日期不丢其他字段。
2. 单测覆盖日期往返及跨时区显示，避免选择某天后显示为前一天。
3. 运行完整 JVM 单测、Python 评测脚本单测、`assembleDebug` 和 `git diff --check`。
4. 有可用模拟器或真机时验证设置、修改、清除、取消、重启持久化；若无设备，明确报告 UI 尚未运行验证。
