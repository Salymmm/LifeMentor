# 任务执行功能

用户已确认继续实现推荐的前三项：今日任务中心、可操作提醒、不依赖 AI 的手动行动。

- 首页展示活跃目标下未完成的每日行动，按设备当地日期分为今天、待重新安排、未来和未安排。每项显示所属目标及日期，支持完成和移到明天；未来任务按日期排序，未安排任务可安排到今天。
- 用户不需要 API Key 就能在新目标下添加行动；新行动默认今天，独立行动在目标详情中直接显示。既有 AI 拆解树保持不变。
- 通知默认关闭，由用户开启并授予 Android 通知权限。每天约当地 8 点提醒一项今天到期行动；没有今天任务时提醒一项明日到期行动。WorkManager 可能因系统省电延迟，不保证精确时间。
- 通知按钮支持完成、1 小时后提醒。重复完成不撤销任务、不重复奖励 XP。延后提醒执行时重新核对任务、目标状态、日期、通知开关及权限；清空数据和关闭提醒会取消后台工作及通知。
- 设置页增加提醒开关、权限状态、测试提醒入口。通知文案完全在本地生成。
- 首页在切回前台时重新读取数据，反映从通知完成的任务。日期跨天也会更新。
- 用户明确禁止随意修改 B 的 AI 部分。本次不修改 llm/、导师聊天、提示词、拆解协议、评测脚本。发现其问题先询问用户。
- 保留现有工具链和存储；仅新增 WorkManager 依赖。本地分支工作，不推送。

验收：分组边界、活跃目标过滤、跨时区日期、完成幂等、手动行动可见性、通知候选与延后失效规则有针对性测试；完整 JVM/Python 回归与 APK 构建通过；尝试设备验收，任何未能完成的界面验证明确报告。

设备检查仅用于临时模拟器。测试文件与偏好使用独立目录，但通知和 WorkManager 属于应用级系统状态；原生测试必须显式传入 `-e disposable true`，否则拒绝执行。不要在日常使用的手机上运行该测试。
